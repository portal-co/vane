# Vane Tools

This folder contains the canonical tester for vane: a TypeScript/Node.js script that
loads the `wasm-pack`-built package and drives a RISC-V ELF binary through the
emulator entirely inside Node.js.  No native Rust binary is involved — vane runs as
WASM inside the JS engine, exactly as it does in the browser.

## Why WASM-in-JS, not a native CLI

vane's public API is generated by `wasm-bindgen`.  The async entry points
(`interp`, `jit_run`) return `JsValue`-based futures that are only meaningful inside
a WASM host (browser or Node.js wasm runtime).  A native Rust binary cannot drive
them with `futures::executor::block_on` — the `JsValue` type does not exist outside
that environment and the generated glue relies on JS engine primitives.  Running the
emulator as a `wasm32-unknown-unknown` module loaded by Node.js is therefore the
correct and only supported way to test from the command line today.

## Prerequisites

- Node.js 16+
- npm
- Rust toolchain with the `wasm32-unknown-unknown` target
- `wasm-pack` installed

## Build the WASM package

From the repo root:

```bash
cd crates/vane
wasm-pack build --target nodejs --out-dir pkg
```

## Build the TypeScript tester

From the repo root:

```bash
npm install
npm run -w tools build
```

This compiles `tools/vane-tester-wasm.ts` into `tools/dist/vane-tester-wasm.js`.

## Run

```bash
node tools/dist/vane-tester-wasm.js --input ./path/to/riscv.elf [flags]
```

### Flags

| Flag | Default | Description |
|------|---------|-------------|
| `--input <path>` | *(required)* | Path to the RISC-V ELF binary |
| `--jit true\|false` | `true` | Use JIT (`true`) or interpreter (`false`) |
| `--test_mode` | off | Enable HINT-based test logging |
| `--paging legacy\|shared\|both` | `legacy` | Paging mode |
| `--shared_page_table_vaddr <n>` | — | Virtual address of shared page table |
| `--shared_security_directory_vaddr <n>` | — | Virtual address of security directory |
| `--use_32bit_paging` | off | Use 32-bit page table entries |
| `--use_multilevel_paging` | off | Use 3-level page tables |

## Troubleshooting

- **`Expected wasm pkg at … - build it first`** — run `wasm-pack build --target nodejs --out-dir pkg` inside `crates/vane`.
- **TypeScript build errors** — run `npm run -w tools build` from the repo root to see the full compiler output.

## Future plans

### 1 · Automated testing via WASM-in-JS

The current tester is a manual CLI.  The next step is to integrate it with the
repository's test runner so that RISC-V ELF test binaries (built by the harness under
`harness/`) are loaded and executed automatically via this same Node.js + WASM path
as part of `npm test` / CI.

### 2 · Native testing via a WASM-interpreter host

Rather than spinning up a JS engine, a future native test runner would embed a
lightweight WASM interpreter (e.g. `wasmtime` or `wasmi`) directly in a Rust binary.
This binary would load the `wasm32-unknown-unknown` output of `crates/vane`, call the
same `interp`/`jit_run` entry points through the interpreter's host API, and report
results as ordinary `cargo test` outcomes.

This approach keeps the execution environment honest — the emulator still runs as WASM
— without requiring a JS engine, making it suitable for pure-Rust CI environments and
removing the need to mix runtimes for automated testing.
